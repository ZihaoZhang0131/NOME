# 渐进问答

## 开场与节奏

用户进入问答后，先读取相关正式记录和已保存草稿，简短说明：“我会先了解一个概览，一次一个问题；你可以跳过、暂停，结束后再决定保存哪些内容。” 不要求用户先填一张问卷，也不依赖其他 Skill。

默认约 5–8 个主问题，已经清楚的信息略过。每轮只问一个主问题，给至多 2–3 个有区分度的选项并允许自由回答；涉及经历、动机时优先用开放问题。回答模糊但不影响后续建议时不反复追问。每 5 轮做一次短小结，用“我目前理解的是……”暴露误解，并提供继续、深入一个主题或结束的选择。

## 概览路线

围绕用户的真实情况灵活排序，不机械逐项完成。默认顺序如下：

1. **身份与处境**：“你现在扮演哪些角色，处于怎样的阶段？”覆盖工作与生活，不预设用户一定求职；当前责任与生活条件也在这一类。
2. **动机与价值**：“眼下有什么是你真想投入的？”必要时再问为什么值得或愿意作何取舍；允许暂时不确定。
3. **特质与偏好**：“做事或与人协作时，什么方式通常让你更舒服？”从具体例子理解喜欢和回避什么，不把一次选择固化成性格。
4. **能力与经验**：“有什么你实际做成的事，能说明你会做什么？”从行为、结果和实践证据理解能力，不诱导自我夸大。
5. **关系与连接**：“有哪些人或群体，对你理解自己很重要？”可以只描述关系，不要求姓名或第三人的敏感信息，尊重跳过。
6. **经历与变化**：“有没有一段经历，让你看待自己或做事的方式发生变化？”关注塑造与变化，不把经历自动当作能力证明。
7. **纠正与选择**：按 [domains.md](domains.md) 的边界复述关键认识，请用户纠正误解，并选择是否深入某个主题。无法确定归属的内容先待分类。

## 深入一个主题

沿“想要什么 → 为什么重要 → 有过什么经历 → 有哪些限制 → 能接受哪些取舍”追问。先找最可能改变建议的未知项，而不是固定问满五遍。必要时用具体对比检验理解，例如：“如果新机会成长快但每周多占用两晚，你会如何权衡？”这只是澄清场景，不替用户做决定。

停止条件：当前主题的目标、关键限制与主要取舍已经清楚；后续问题不再改变理解；用户疲倦、要求暂停、跳过或结束。不要以资料百分比作为继续追问的理由。

## 保存、跳过、恢复

- “跳过”只表示不回答本轮问题。只有用户明确表示该领域不适用或不愿提供，才在最终保存草稿中提出相应领域状态。不得把敏感话题跳过推断为个人事实。
- 问答默认仅在对话中积累。结束时展示精简的拟保存内容，并区分用户原话、概括和不确定项。一次确认后，用 `save-interview` 提交；未确认的不确定项不得标为 confirmed。
- “先停一下”只停止问答，不写文件。“保存一下进度”才以 `save-progress` 写结构化草稿；不保存完整聊天记录。下次 `read --drafts` 读取已获得的回答，告知恢复点后继续。草稿不用于普通建议。
- 用户确认草稿后，使用同一个记录 ID，写入 `target: records`；程序将记录从草稿移动到正式档案。保存草稿中的用户回答可使用 `imported`（尚未复核）状态，不把它冒称为 Agent 推测；source 保留 user。
- 用户说“先不要保存”则结束，任何档案版本都不应改变。

完整写入示例见 [protocol.md](protocol.md)。
