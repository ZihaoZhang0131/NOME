# 显式更新与纠正

## 识别授权范围

“帮我更新个人档案：我每周可用时间变为 4 小时”已经授权该修改；读取相关领域、定位 ID、提交、反馈即可。“我现在每周只有 4 小时，你建议怎么学”是在提供当前咨询上下文，不是授权长期保存。按新信息回答，但不写入。

“帮我更新”结合当前对话能唯一确定对象时继续；对象或内容不清楚时问一个聚焦问题，不从整段聊天中自行挖掘所有信息。不要反复确认已经明确授权的修改。

## 提交流程

1. 读取相关领域，保留 revision 与记录 ID。来源冲突需要当前用户澄清；不能仅按文件新旧覆盖。
2. 按 [protocol.md](protocol.md) 构造最小修改。更新已有事实复用 ID；新信息新增 ID；由用户直接明确提供的事实使用 source user、status confirmed。
3. 写入成功后重新读取相关领域验证，用一句话说明保存了什么。失败则说明原因，不宣称已经记住。
4. 遇到 `REVISION_CONFLICT` 重新读取并比较本次修改涉及的记录，确保没有覆盖另一个 Agent 的变更；不只替换版本号重试。`WRITE_LOCKED` 只在现有写入结束后重试。无法判断锁是否失效时停止，不自动删除锁。

## 删除与撤销

- “撤销刚才的修改”调用 `undo`，撤销最近尚未撤销的有效 apply 操作。版本号仍递增。彻底删除不能撤销。
- “删除这条／忘掉这条”定位明确 ID 后调用 `forget`。该记录正文与来源从当前正式档案、草稿及所有 NOME 历史快照移除，不保留可恢复副本。用户同时要求删除同义重复记录时，列出匹配范围并一并删除；否则不要扩大删除范围。
- 如果同一事实曾被录入多个不同 ID，程序不会做语义消除，Agent 需按用户要求识别范围。删除不会修改宿主记忆、旧聊天、操作系统备份或用户另行导出的文件。用户要求跨这些位置删除时，应单独说明所需操作，不能宣称 NOME 已删除外部副本。
- “暂不提供这个领域”更新该领域 state 为 withheld；不永久删除已保存记录。普通读取不再返回这些记录，页面说明该领域已跳过。需要彻底清除时才使用 forget。
