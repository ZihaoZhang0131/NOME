# 保存 修改与删除

“帮我更新”“整理入库”“先保存聊过的部分”等清楚指令已经授权相应修改，不重复确认。“我每周只有四小时，你建议怎么学”只提供咨询背景，不自动长期保存。

1. 按 [domains.md](domains.md) 选主要归属，用 read 读取当前正文和 hash。
2. 合并成连贯文档或章节，替换不再适用的描述，保留其他正文。不要把普通回答改写成超出原意的结论；冲突不明确时只核对冲突点。
3. 使用 [protocol.md](protocol.md) 的 write/delete 操作提交。内容只有入库或不入库，不写入待核实、来源或系统操作时间。
4. 重新读取验证，再用内容层面的语言说明更新了哪个模块。出现 CONTENT_CONFLICT 时重新读取和合并，不只换一个 hash 强行覆盖。

删除一段内容时提交删除后的整篇 Markdown，删除整份文档使用 delete。移除一个模块时包括它的各章，不留下无入口的子文件。本版本不保留常规撤销历史，删除后不能用 NOME 恢复。用户外部备份、聊天和宿主记忆不在删除范围。

旧迁移副本 store.json 默认保留且明确报告，不参与读取；用户要求跨该副本删除时需另行处理整个副本或对应旧数据，不能宣称修改 Markdown 会自动清理外部旧资料。
