# NOME 初始化 档案管理与问答体验优化方案

NOME 将个人档案改为由用户掌控、可直接阅读的 Markdown 文档。初始化先利用本地 Agent 的已有记忆，缺少来源时让用户选择其他来源或直接补充；管理页面只展示正式入库正文；问答先建立全面脉络，再进入局部深入与日常更新。

本次范围包括 Skill 指令、初始化来源发现、档案存储与读写协议、可视化页面及旧数据迁移。本方案作为 0.2 改造的产品与验收依据；个人数据通过显式迁移处理。

# 一 需要解决的体验问题

| 环节 | 本次交互暴露的问题 | 目标体验 |
| --- | --- | --- |
| 初始化 | 默认两个文件不存在后直接进入问答，用户需要主动提出其他记忆来源 | 优先检查本地可用记忆；没有可读内容时，明确提供指定来源与直接补充两条路径 |
| 档案管理 | 档案拆成条目，附带来源、确认时间、更新日期、导入状态等信息 | 每个模块由一个或多个完整 Markdown 文件组成，打开即阅读正文 |
| 中间内容 | 已保存页面混有已确认、待核实、推测、草稿等状态 | 内容只有入库与未入库两种处理结果；未入库内容留在对话中 |
| 问答范围 | 经历与变化从“举一段经历”切入，未先建立人生脉络 | 先梳理从出生至今的主要阶段与变化，再根据缺口深入 |
| 后续问答 | 每次重新抛开放问题，缺少对已有档案的回顾 | 先介绍当前已了解的情况，再问最近发生的变化和需要补充的内容 |

六个领域继续作为整理个人叙述的框架，允许用户调整章节。页面与问答都围绕理解用户展开，不使用条目数、覆盖率或人格评分衡量认识程度。

# 二 初始化流程

## 本地记忆优先

用户明确要求初始化后，先检查已有 NOME 档案，避免覆盖已有正文；然后利用当前上下文中已经提供的个人记忆，检查宿主公开的记忆能力及已知本地记忆文件。

来源发现需要区分四种结果：找到可读内容、来源存在但内容为空、来源存在但暂时无法读取、未找到受支持的来源。默认文件缺失只能说明该入口没有内容，不能据此判断 Agent 没有记忆，更不能判断用户没有相关经历。

本地数据库只能作为已识别版本的适配入口；存在数据库文件不等于存在可导入记忆。对未适配格式应明确说明支持边界，不继续猜测内部表结构或扫描全部聊天记录。来源始终只读。

## 找不到内容时给出选择

用一段简短说明交代结果，然后询问：“本地暂时没有找到可读取的记忆。你想指定其他来源，还是直接和我一起补充？”

提供的选择可以是：

- 指定文件、文档或已有记忆摘要的位置。

- 指定 ChatGPT 网页版记忆管理等来源，由 Agent 通过可用工具读取。

- 不导入旧资料，直接开始全面梳理。

不要求用户必须上传文件或重答整张问卷。用户已指定位置后直接读取，不再重复询问是否允许查找。遇到登录或不可访问问题时，说明具体障碍并给出继续路径。

## 从记忆整理成完整正文

按六个领域合并相关信息，消除同义重复，整理为有章节的自然语言。保留记忆中实际提供的细节，不为了凑齐六个模块推断信息，也不把一次任务行为概括成稳定性格。

内容有冲突或语义不明时，在当前对话中核对；未解决的内容不入库。用户选择导入某批内容后，这批内容就是正式正文，不再赋予“导入待核实”的长期状态。

首次保存前可以展示六个领域的简短概览，用户需要时再展开全文。用户已明确说“按这份内容保存”或“用这份记忆初始化”且范围清楚时，直接执行，不重复索取同一授权。

完成后只反馈保存了哪些模块及如何查看，不向用户汇报内部版本号、记录 ID 或技术校验字段。

# 三 Markdown 档案存储

## 正文是唯一事实来源

以 Markdown 文件替代当前以 store.json 为核心的条目模型。Agent 和页面读取同一套文件，手动修改 Markdown 后，下一次读取或刷新即可反映结果。

每个领域默认一个完整文件；内容变长后可拆为多个有意义的章节文件。拆分应依据阅读需要，不强制每条事实单独建文件。建议目录如下：

```text
~/.nome/
  profile/
    identity/
      index.md
    motivation/
      index.md
    traits/
      index.md
    capabilities/
      index.md
      selected-projects.md
    relationships/
      index.md
    growth/
      index.md
      childhood-and-school.md
      university.md
      career.md
```

以上章节仅是结构示例，不代表已经了解用户具有这些经历。各领域 index.md 是模块入口；拆分后通过相对链接或明确章节目录组织阅读顺序，不重复维护相同段落。尚无内容的模块可以没有文件，或保留空文件；不生成“待了解”的档案正文。

默认沿用现有数据目录选择规则，支持 NOME_DATA_DIR 与显式数据目录。Skill 安装目录与个人资料目录继续分离。

## 移除条目元数据和内容状态

正式档案不保存或要求填写以下字段：

- 来源类型、引用路径、导入标记。

- 创建时间、更新时间、确认时间。

- imported、inferred、confirmed、drafts 等状态。

- 每条事实的 ID、版本标签和确认流程记录。

不通过 YAML frontmatter、隐藏 JSON 或另一份状态表重新引入这些字段。出生年份、就读阶段、任职时间等人生经历中的时间仍属于正常正文，可在用户提供后记录；它们与系统记录的操作时间不同。

内容只分为：已入库的正式 Markdown，以及尚留在当前对话中的内容。暂不落库的猜测、冲突和讨论不进入正式目录、读取结果或可视化页面。

## 写入与恢复

更新以现有文件为基础，定位章节后合并或改写，避免每次追加一条导致重复。跨模块的同一信息选择一个主要归属，必要时使用链接。

内部仍需防止并发覆盖和半写入：写入前核对当前文件，使用临时文件与原子替换；跨文件操作先完成校验，提交失败时恢复本次变更。文件校验值和锁只服务写入安全，不作为用户档案字段。

常规运行不默认保存包含旧正文的独立历史库，避免把已删除内容长期留在另一份记录中。如保留撤销功能，需要明确恢复范围和删除语义；“忘掉这条”必须同步处理 NOME 自己保留的相关副本。

# 四 可视化页面减法

保留现有个人星图作为六个模块的入口。点击模块后展示 Markdown 文档，长内容通过章节导航阅读，多文件内容使用清晰的目录跳转。

页面只保留理解和阅读所必需的内容：

| 位置 | 保留 | 移除 |
| --- | --- | --- |
| 星图入口 | 六个模块名称、可点击入口 | 已确认数量、待核实数量、草稿数量、覆盖进度、资料完整度暗示 |
| 模块详情 | 模块名称、章节导航、正文、返回与切换 | 条目状态徽标、来源、参考路径、确认时间、更新时间 |
| 空模块 | 一句“这里还没有内容” | 多段解释、提示词清单、重复的问答引导 |
| 页面辅助区域 | 必要的导航和错误提示 | 存储协议、内部版本、记录 ID、持久化状态说明 |

文本按标题、段落、列表、引用和链接正常渲染，不再给每条事实套状态卡片。“经历与变化”直接显示按阶段组织的叙述；正文足够丰富时才显示目录。

简化产品界面不意味着把档案内容压缩成几个短标签。页面辅助文字做减法，用户的实际经历和叙述保留应有的完整性。

页面继续支持桌面和手机阅读、键盘操作、浏览器前后导航；默认保持只读，更新仍由 Agent 对话完成。刷新读取当前文件。迁移预览和对话草稿不会出现在星图页面。

# 五 全面梳理的问答模式

## 先建立全貌，再深入局部

进入问答先读现有模块，并用简短回顾说明已了解的范围和明显缺口。首次材料不足时，给出本模块的整体梳理路线；已有较完整内容时，直接进入回顾和更新。

不再固定每轮只能从一个小问题或一个例子切入，也不机械规定问满五到八轮。一次可以围绕一个阶段给出少量相关提示，让用户连续讲述。用户可长篇叙述、按提纲回答、跳过某段或直接纠正回顾。

“全面”是覆盖主要阶段和维度，不要求事无巨细，也不要求提供精确日期、敏感经历或第三人的隐私。篇幅长不自动等于了解全面，某一阶段没有讲述也不自动等于用户没有相关经历。

## 经历与变化的默认路线

先从出生到现在建立阶段骨架，再逐段了解环境、经历、选择以及它们带来的变化：

| 阶段 | 可引导的内容 |
| --- | --- |
| 出生与成长环境 | 大致成长背景、生活环境、家庭氛围与早期影响 |
| 童年与基础教育 | 学习和生活体验、兴趣、与人相处、重要记忆 |
| 青少年阶段 | 自我认识、价值观、重要选择与关系变化 |
| 高等教育或进入社会 | 专业或路径选择、探索、转折与适应 |
| 工作与成年生活 | 职业阶段、工作之外的生活、重要责任与选择 |
| 近期与当下 | 最近的转型、变化、正在重新理解的事情 |

阶段根据用户经历调整，不预设一定上过大学、一直在工作或已经组成家庭。用户愿意时补充关系、居住环境和生活重心的变化，不把人生叙述全部收窄为职业履历。

每段围绕三个线索自然展开：当时是什么情况、发生了什么、后来有什么改变。不需要逐项问出标准答案。用户讲完某一段后先整理已有叙述，再询问下一段或最重要的缺口。

旧问题“有没有一段经历让你发生变化”可在整体脉络建立后，用于深入某个转折，不再作为首次梳理的默认开场。

## 其他模块也需要整体视角

| 模块 | 全面梳理的范围 |
| --- | --- |
| 身份与处境 | 当前角色、人生阶段、责任、生活条件及现实限制 |
| 动机与价值 | 工作与生活中想投入的事、近期与长期方向、重视之事及取舍 |
| 特质与偏好 | 学习、做事、决策、协作、沟通、休息中的常见模式与偏好 |
| 能力与经验 | 工作与个人实践、实际承担的职责、具体成果、能力边界与希望补足的部分 |
| 关系与连接 | 重要关系、支持网络、群体归属及相处方式；不要求提供姓名 |
| 经历与变化 | 从早期成长到当下的主要阶段，以及跨阶段形成的变化 |

各模块按用户实际情况组织。全面梳理不是一次性把所有维度问完，而是让用户知道整体路线、已讲到哪里、接下来补什么。

# 六 已有档案后的回顾与更新

档案已经覆盖主要阶段后，再进入问答时先介绍当前理解，再询问近期是否有变化或需要补充的内容，不从头重问，也不凭文件长度宣称已经全面了解。

例如：“现有经历已经覆盖成长、求学和几段工作阶段，近期主要围绕向 AI 全栈和 Agent 工程拓展。我们还没有谈到工作之外对你有影响的经历。你想补充这部分，还是先更新最近的变化？”

以上为交互示例，不是当前用户已有完整经历档案的陈述。

用户选择更新时，只追问会影响正文的内容：新近发生的变化、旧描述是否仍适用、是否需要改写或移除。用户选择继续全面梳理时，回到尚未展开的阶段。用户只想查看现状时，给出回顾即可。

不设固定更新周期，不自动推送提醒，也不为增加内容而重复提问。

# 七 保存交互

普通问答内容先在对话中整理，不自动进入档案；用户明确说“整理入库”“保存这一段”“按刚才的内容更新”时，已构成对范围明确内容的保存授权，直接执行。

保存结果是可阅读的完整章节。Agent 合并重复表达、保持原意，不补写用户没有表达的人格判断、因果关系或能力评价。涉及较大重构时，展示有实质变化的段落；内容有冲突时，仅就冲突点澄清。

不再要求用户理解“保存草稿”“导入待核实”“转为正式记录”等技术流程。用户说“先不保存”或“暂停”时，正文保持原状；用户说“先保存聊过的部分”时，把明确的内容写成正式章节，尚未讲述的阶段以后继续补充。

用户希望下次继续时，可以在对话中概括停在哪一阶段；如要持久化单独的继续位置，另做可选会话功能，不能把未完成问答混进个人档案正文或页面。

保存完成后用一句话说明更新了哪个模块和什么内容，并在必要时提示刷新页面。

# 八 旧数据迁移

现有个人档案包含已确认和已导入的混合记录，迁移需要重新整理内容，不能只把 status 字段隐藏。

1. 只读解析旧 store.json，收集正式记录、草稿、待分类内容和可能的重复或冲突。

2. 将正式记录按语义组织成六个领域的 Markdown 候选正文，去掉来源和操作时间等元数据。不同旧状态不再映射为新的正文标签。

3. 在对话中核对有冲突的内容，并让用户选择迁移范围。旧草稿和待分类内容不默认进入正式目录。

4. 用户选择保留的内容直接写为正式正文；未选择或尚未解决的内容不进入新档案。

5. 迁移在独立临时目录构建并验证，成功后切换读取入口。失败时保留旧档案可继续读取，不留下半成品页面。

6. 旧 store.json 仅作为显式迁移回退副本处理，不继续参与日常读取或展示。保留或清理由用户选择；回退副本中仍含旧元数据，不能把“已迁移”等同于“已清除旧文件”。

验收时核对六个模块内容是否完整、重复是否已合并、用户没有选择的内容是否被排除，并确认后续 Agent 和页面都只读取新 Markdown。

# 九 改造位置和实施顺序

以下路径为 NOME 仓库内路径，应在源码仓库实现后再升级安装副本。

| 位置 | 改造内容 |
| --- | --- |
| skills/nome/SKILL.md | 重写入口路由，明确正式 Markdown、全面梳理、回顾更新及明确保存即执行 |
| references/initialization.md | 改为本地优先、来源状态区分、找不到时给用户选择、导入后即正式正文 |
| references/interview.md | 引入全面梳理、局部深入、回顾更新三种路线，替换单事例默认开场 |
| references/domains.md | 保留六类含义，增加章节组织与跨模块内容归属规则 |
| references/updating.md 与 protocol.md | 由条目状态协议改为文档和章节读写，明确写入校验与冲突处理 |
| scripts/lib/sources.mjs | 完善来源适配、空内容判断与可读性报告 |
| scripts/lib/store.mjs 与 model.mjs | 使用 Markdown 文档模型，移除档案状态与业务元数据；实现安全读写和旧数据迁移 |
| scripts/lib/server.mjs 与 scripts/nome.mjs | 调整 CLI 与页面接口，按领域提供正文和章节，不再返回待核实列表 |
| assets/app.js 与 profile-view.js | 由记录卡片渲染改为模块文档阅读，删除状态统计和来源时间展示 |
| assets/style.css 与 index.html | 简化辅助文字和卡片样式，优化长文阅读、章节导航和移动端 |
| assets/demo.json、README.md、测试与评测资料 | 将演示、使用说明和验证场景同步为新模型，避免文档与运行行为不一致 |

第一步先统一产品规则和写入边界，完成新指令与真实问法的评测场景。第二步实现 Markdown 存储、CLI、迁移和服务接口。第三步改造页面并更新示例。最后从全新用户与已有档案两条路径进行完整验证。

存储、协议和页面应作为同一版本交付，避免正文已改为 Markdown 而页面仍依赖旧状态字段。

# 十 验收标准

## 初始化

- 本地存在受支持的个人记忆时，优先读取并整理，用户不需要先重新自我介绍。

- 默认文件缺失而其他受支持入口有内容时，不提前判定“没有记忆”。

- 来源为空、不可读和未找到能明确区分；找不到时主动给出指定其他来源与直接补充的选择。

- 用户指定 ChatGPT 网页版记忆摘要后，可以读取并整理；缺少浏览器访问条件时给出具体继续路径。

- 用户明确同意导入的内容保存为正式正文，不产生待核实状态。

## 存储和页面

- 直接打开各领域 Markdown 可以读到完整叙述；多文件模块有清晰入口和顺序。

- 修改 Markdown 后，Agent 下次读取和页面刷新展示同一份内容，无需同步到另一套事实数据库。

- 正式目录和页面均没有来源、确认时间、更新时间、记录状态、草稿或待分类面板。

- 人生经历中的实际时间正常保留；系统操作时间不混入正文。

- 页面不展示确认数量、覆盖率或完整度评分；空模块只有简短提示。

- 旧数据迁移失败不影响原档案；成功后正式读取路径完全切换。

## 问答与保存

- 对“补充我的经历与变化”，先回顾现有内容，给出从出生至今的阶段路线，再进入具体阶段。

- 面向其他模块时也先明确全貌，不能用一个小例子代替整体梳理。

- 用户提供长篇叙述后，能整理时间脉络和变化，接着补关键缺口，而非机械重复提问。

- 已有较完整内容时，先回顾现状，再问最近的变化或需要补充的地方。

- 用户要求“整理入库”时保存明确内容，不再追问是否要保存，也不把结果写成待核实记录。

- 用户暂停、跳过或拒绝回答时，尊重其选择，不推断缺失事实，不自动保存。

- 保存或迁移后重新读取验证；权限错误、并发冲突及服务错误不会被报告为成功。

验证同时覆盖程序行为与真实 Agent 对话。程序测试检查 Markdown 读写、迁移、接口与页面；对话评测检查初始化选择、全面梳理、回顾更新和保存授权是否符合上述体验。
